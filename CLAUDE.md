# Agent Notes

- Toolchain: Zig 0.16.0, stdlib-only; binary name `linear`. Run `zig fmt` on touched Zig files and prefer `zig build test` for verification (online smoke optional via `LINEAR_ONLINE_TESTS=1` + `LINEAR_API_KEY`).
- Config: `~/.config/linear/config.json` (0600). Defaults: team ``, output `table`, state filter excludes `completed`/`canceled`.
- Credential chain: `LINEAR_API_KEY` > `credential_helper` > macOS keychain > config file (deprecated, warns). The helper outranks the keychain on purpose — explicit configuration must beat auto-detection, otherwise a configured helper is silently ignored and the secret's location fragments. `config.load` applies only the two ends (file key, then the env override); `credentials.resolve` fills in the middle and is called once from `main.zig`. Invariant to preserve: only a `.file`-sourced key is ever written to disk (`Config.file_api_key`), and a provider-sourced key must never *delete* the key already on disk — `KeySource.isEphemeral` is the single check. A configured helper that fails clears the effective key and stops; it must never fall through to the plaintext file it was configured to replace.
- `credential_helper` is an argv **array**, never a command line. No shell, ever. A bare string is split on whitespace with no shell semantics (documented as quoting-unsupported). A backend's stdout is the secret: never log, print, or quote it in a diagnostic — failures report exit status and stderr only.
- Keychain: read is `security find-generic-password -w -s linear-cli -a api-key` (secret returns on stdout, argv is clean). Write goes through `security -i` with the `add-generic-password` line on **stdin**, because `add-generic-password -w <secret>` would publish the key in the process table — the exact hazard `--api-key` was removed for. There is no argv fallback; a key that would be misread as a flag is refused instead. Gate everything on `credentials.keychain_supported` (`builtin.os.tag == .macos`); do not downgrade to the file on other platforms.
- Removing a secret from the config file goes through `Config.saveScrubbed`, which overwrites the old bytes before the truncate-and-rewrite. Plain `save` truncates, which leaves the old key readable in freed blocks.
- Auth header must be `Authorization: <key>` (no Bearer). Do not alter endpoint `https://api.linear.app/graphql`.
- Command surface: global `--json`/`--config`/`--help`/`--version`; subcommands `auth set|test|show|status|migrate`, `me`, `teams list`, `labels list`, `users list`, `states list`, `projects list`, `issues list`, `issue view`, `issue create`, `issue update`, `issue comment [list|update|delete]`, `issue start`, `issue pr`, `issue id|url|title|describe`, `project create|update`, `milestone list|view|create|update|delete`, `gql`. List pagination is a stub—warn when more pages remain. The one real cursor walk is `gql --paginate`.
- `issue comment` dispatches on its first argument: `list`/`update`/`delete` route to `src/commands/issue_comments.zig`; anything else is an issue identifier for the comment-create path in `src/commands/issue_comment.zig`. Keep `isSubcommand` as the single source of truth for that split.
- Long-form text fields take a companion `--*-file PATH` flag (`--description-file`, `--body-file`, `--content-file`) where `-` means stdin. Do not hand-roll the read: use `common.resolveContent`, which enforces the mutual exclusion with the inline flag, caps input at `common.max_content_bytes` (1 MiB), and reports both failures with an explicit message. Resolve content before `requireApiKey` so a bad path never costs a request.
- `Project.description` is capped at 255 characters by Linear; long project text must go to `Project.content` via `--content`/`--content-file`. Never widen `--description` to carry it.
- Anything written to disk that came from issue content is created 0600 (`issue view --attachment-dir`, `linear download --output FILE`, the config file). New file-writing paths must match.
- Enumeration commands (`teams`/`labels`/`users`/`states`/`projects list`/`milestone list`) exist so raw ids never have to be hand-written: `labels list` feeds `--label`, `users list` feeds `--assignee`, `states list` feeds `--state-id`, `milestone list` feeds `--milestone`. Any new list command must ship the machine-readable flag set from day one (`--fields`, `--quiet`, `--data-only`, `--plain`, `--no-truncate`, `--limit`, plus `--json` via `ctx.json_output`).
- Adding a list command means touching four places: `src/print.zig` (field enum + `*_default_fields` + `*Row` + `print*Table` + the `*FieldLabel`/`*FieldCap`/`fill*Cells` trio — duplication per entity is deliberate, there is no generic table), `src/commands/<name>.zig`, `build.zig` (a `*_mod` on `graphql_mod`/`common_mod` **and** a `*_test_mod` on `graphql_mock_mod`/`common_test_mod`), and `src/main.zig` (dispatch + `routeHelp` + `printUsage`).
- Only fetch sub-selections that were asked for. `issues list` gates its `children(first:)` sub-query on the `sub_issues` column being selected or `--sub-limit` being passed explicitly; do not reintroduce unconditional sub-queries.
- `src/process.zig` is the ONLY place that starts a child process; `git.zig` re-exports its `Runner`/`Captured`/`Exit`/`Error` so git call sites still read as `git.Runner`, and `credentials.zig` uses it directly. Do NOT add a second spawning path. Two invariants: argv is always an explicit array (never a shell string, never `sh -c`, never interpolation — issue titles, branch names, and helper commands are attacker- or operator-influenceable and may only appear as discrete argv elements), and every spawn goes through `Runner` so pure logic stays testable. Ref arguments pass `git.validateRefArg` (rejects empty, leading `-`, whitespace/control bytes) before any spawn. Map `SpawnError.FileNotFound` to `BinaryNotFound`; a subprocess failure must surface as `<prefix>: <message>` on stderr with a non-zero exit, never a panic.
- `Runner.capture` is the plain form; `Runner.captureWith` adds `CaptureOptions` (stdin bytes, stdout/stderr limits, timeout). Feeding stdin exists so a secret can reach a child without touching argv; it is capped at `process.max_stdin_bytes` (4 KiB) because the whole payload is written before either output stream is drained, so it must fit in one pipe buffer or the two processes deadlock.
- Commands carry `git_runner: ?git.Runner = null` (and `auth` carries `credential_runner: ?process.Runner = null`) on their `Context`. `null` means "no process execution", which is what keeps tests hermetic: `main.zig` installs the system runner, tests inject `FakeProcess` (`src/tests/main.zig`), and no test ever shells out or depends on this repo's branch. Never default those fields to the system runner.
- `git.zig` imports only std and `process`, and `credentials.zig` only `config` and `process` — none of which has a mocked variant — so a single `git_mod`/`process_mod`/`credentials_mod` serves the exe, both command module variants, and the npm cross-builds. There is deliberately no `*_test_mod` for any of them.
- Branch inference is `git symbolic-ref --short HEAD` plus `git.matchIdentifier` (leftmost `\b([A-Za-z0-9]+)-([1-9][0-9]*)\b`, team key uppercased). Detached HEAD is not an error — it is a distinct result, told apart from "not a git repository" by a `git rev-parse --is-inside-work-tree` probe. Do not slugify branch names locally: `issue start` uses Linear's own `Issue.branchName`.
- `linear milestone` keeps all five verbs in one module (`src/commands/milestones.zig`) the way `issue_comments.zig` does: they share the `ProjectMilestone` field projection, the project resolver, and the sort-order renderer. `--project` accepts a uuid (no lookup), a slug, or an exact name; a name that matches more than one project is an error, never a silent pick. `sortOrder` is a GraphQL Float, so it leaves as a JSON number, not the string the flag arrived as.
- `--bulk`/`--bulk-file`/`--bulk-stdin` on the delete commands go through `src/commands/bulk.zig`, which owns flag parsing, dedupe, and per-item accounting. It is separate from `common.zig` on purpose — `common.zig` is the GraphQL request/response layer, this is batch bookkeeping. Execution is **serial and must stay that way**: every caller is a destructive mutation and nothing else in this codebase runs concurrently. A per-item failure is counted and the run continues; only writer/allocator errors abort. The summary line goes to stderr and is suppressed under `--json`, where per-item documents are wrapped in one array instead.
- `gql --paginate` validates the document up front (`$after` must be *declared*, not just referenced; `pageInfo`/`hasNextPage`/`endCursor` must all appear) and finds the connection breadth-first in the response, so the shallowest `nodes`+`pageInfo` object wins. Every page's `Response` is kept alive until printing because the merged document borrows node values from all of them — same reason `issues.zig` accumulates whole responses. `--max-pages` (default 20) is the loop bound; hitting it warns on stderr and still returns what was collected.
- GraphQL client already handles HTTP status + GraphQL errors; retries only for 5xx with small backoff. Preserve explicit error messaging.
- Tests: offline unit coverage exists for config, flag parsing, printer; keep them passing. Online tests are gated by env and should remain optional.
