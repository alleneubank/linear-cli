# Agent Notes

- Toolchain: Zig 0.16.0, stdlib-only; binary name `linear`. Run `zig fmt` on touched Zig files and prefer `zig build test` for verification (online smoke optional via `LINEAR_ONLINE_TESTS=1` + `LINEAR_API_KEY`).
- Config: `~/.config/linear/config.json` (0600). Defaults: team ``, output `table`, state filter excludes `completed`/`canceled`.
- Credential chain: `LINEAR_API_KEY` > `credential_helper` > macOS keychain > config file (deprecated, warns). The helper outranks the keychain on purpose — explicit configuration must beat auto-detection, otherwise a configured helper is silently ignored and the secret's location fragments. `config.load` applies only the two ends (file key, then the env override); `credentials.resolve` fills in the middle and is called once from `main.zig`. Invariant to preserve: only a `.file`-sourced key is ever written to disk (`Config.file_api_key`), and a provider-sourced key must never *delete* the key already on disk — `KeySource.isEphemeral` is the single check. A configured helper that fails clears the effective key and stops; it must never fall through to the plaintext file it was configured to replace.
- `credential_helper` is an argv **array**, never a command line. No shell, ever. A bare string is split on whitespace with no shell semantics (documented as quoting-unsupported) by `config.splitCredentialHelper` — the single parser, used by both the config-file bare-string form and `config set credential_helper`; do not write a second one. A backend's stdout is the secret: never log, print, or quote it in a diagnostic — failures report exit status and stderr only.
- `config set credential_helper "<cmd>"` is the only writer of `credential_helper`, and it **runs the helper before storing it** — the bootstrap path where the key never touches disk. It may not be relaxed into a store-and-hope: a configured helper that fails *clears* the effective key instead of falling through, so a stored-but-broken helper locks the operator out. It checks `config.validateCredentialHelper` bounds before spawning, and `config unset credential_helper` must stay key-free and spawn-free — it is the escape hatch.
- There is deliberately **no migrate command**. Write-then-verify-then-scrub carried real complexity and still had to tell the operator to rotate the key, because scrubbing cannot beat APFS copy-on-write, snapshots, or backups. If the key must be rotated anyway, moving it buys nothing over deleting `~/.config/linear/config.json` and setting up fresh — which also clears `default_team_id` and `team_cache`. Every diagnostic that used to point at `auth migrate` now points at `config set credential_helper` (preferred), `auth set --to keychain`, and delete-then-rotate. Do not reintroduce a move/scrub path.
- `auth status` is **offline and must stay offline**. It may only claim what `config.isValidApiKey` proves, so the label is `present (format-valid, unverified)` and the JSON field is `key_format_valid` with `key_verified` pinned to `null`. Never relabel it as plain "valid", and never make it issue a request — `auth test` is the command that verifies.
- A malformed `credential_helper` in the config file must reach the operator as `config.credentialHelperErrorText`, not as a raw Zig error name. Both call sites (`main.zig`'s `config.load` catch and the command layer) go through it; a new `CredentialHelperError` variant needs a sentence there.
- Keychain: read is `security find-generic-password -w -s linear-cli -a api-key` (secret returns on stdout, argv is clean). Write goes through `security -i` with the `add-generic-password` line on **stdin**, because `add-generic-password -w <secret>` would publish the key in the process table — the exact hazard `--api-key` was removed for. There is no argv fallback; a key that would be misread as a flag is refused instead. `auth set --to keychain` is the only writer, and it reads the item back and compares before reporting success, because `security -i` reports on the session rather than on each command it was fed. Gate everything on `credentials.keychain_supported` (`builtin.os.tag == .macos`); do not downgrade to the file on other platforms.
- Nothing removes a secret from the config file. `Config.save` is the only writer and it truncates, which leaves the old bytes readable in freed blocks — that is exactly why the answer to a plaintext key is "delete the file and rotate the key", not an in-place scrub. Do not add one back: it cannot beat copy-on-write, snapshots, or backups, and it would imply a safety it does not deliver.
- Auth header must be `Authorization: <key>` (no Bearer). Do not alter endpoint `https://api.linear.app/graphql`.
- Command surface: global `--json`/`--config`/`--help`/`--version`; subcommands `auth set|test|show|status` (`auth set` takes `--to keychain|file`, defaulting to `file`), `me`, `teams list`, `labels list`, `users list`, `states list`, `projects list`, `issues list`, `issue view`, `issue create`, `issue update`, `issue comment [list|update|delete]`, `issue start`, `issue pr`, `issue id|url|title|describe`, `project create|update`, `milestone list|view|create|update|delete`, `gql`. Every list command does a real cursor walk (`--limit` page size, `--pages N`/`--all`, `--cursor`, `--max-items`); `gql --paginate` is the generic equivalent for arbitrary documents. `search` is the one command that still cannot paginate.
- `issue comment` dispatches on its first argument: `list`/`update`/`delete` route to `src/commands/issue_comments.zig`; anything else is an issue identifier for the comment-create path in `src/commands/issue_comment.zig`. Keep `isSubcommand` as the single source of truth for that split.
- Long-form text fields take a companion `--*-file PATH` flag (`--description-file`, `--body-file`, `--content-file`) where `-` means stdin. Do not hand-roll the read: use `common.resolveContent`, which enforces the mutual exclusion with the inline flag, caps input at `common.max_content_bytes` (1 MiB), and reports both failures with an explicit message. Resolve content before `requireApiKey` so a bad path never costs a request.
- `Project.description` is capped at 255 characters by Linear; long project text must go to `Project.content` via `--content`/`--content-file`. Never widen `--description` to carry it.
- Anything written to disk that came from issue content is created 0600 (`issue view --attachment-dir`, `linear download --output FILE`, the config file). New file-writing paths must match.
- Enumeration commands (`teams`/`labels`/`users`/`states`/`projects list`/`milestone list`) exist so raw ids never have to be hand-written: `labels list` feeds `--label`, `users list` feeds `--assignee`, `states list` feeds `--state-id`, `milestone list` feeds `--milestone`. Any new list command must ship the machine-readable flag set from day one (`--fields`, `--quiet`, `--data-only`, `--plain`, `--no-truncate`, plus `--json` via `ctx.json_output`) **and** the pagination set (`--limit` as the per-request page size, `--pages N`/`--all`, `--cursor`, `--max-items`).
- The cursor walk is duplicated per entity, not factored into a generic driver — the connection field, node projection, per-node formatting and output modes all differ, and a generic version would need comptime type parameters plus row-extraction callbacks. What *is* shared is `common.printPageSummary`, which owns the closing stderr report (`fetched N items across M pages[; more available, resume with --cursor X]`, suppressed under `--json`, plus the un-suppressed `--max-items` notice) so all six commands cannot drift apart. Copy the loop from `issues.zig`; the load-bearing detail is that parsed fields are slices into each page's `Response`, so every response is accumulated in an `ArrayListUnmanaged` and freed together at the end, rows are re-borrowed from the list rather than from the local after appending, and the `checkResponse` failure path frees by hand because `errdefer` does not fire on `return 1`.
- Adding a list command means touching four places: `src/print.zig` (field enum + `*_default_fields` + `*Row` + `print*Table` + the `*FieldLabel`/`*FieldCap`/`fill*Cells` trio — duplication per entity is deliberate, there is no generic table), `src/commands/<name>.zig`, `build.zig` (a `*_mod` on `graphql_mod`/`common_mod` **and** a `*_test_mod` on `graphql_mock_mod`/`common_test_mod`), and `src/main.zig` (dispatch + `routeHelp` + `printUsage`).
- Only fetch sub-selections that were asked for. `issues list` gates its `children(first:)` sub-query on the `sub_issues` column being selected or `--sub-limit` being passed explicitly; do not reintroduce unconditional sub-queries.
- `src/process.zig` is the ONLY place that starts a child process; `git.zig` re-exports its `Runner`/`Captured`/`Exit`/`Error` so git call sites still read as `git.Runner`, and `credentials.zig` uses it directly. Do NOT add a second spawning path. Two invariants: argv is always an explicit array (never a shell string, never `sh -c`, never interpolation — issue titles, branch names, and helper commands are attacker- or operator-influenceable and may only appear as discrete argv elements), and every spawn goes through `Runner` so pure logic stays testable. Ref arguments pass `git.validateRefArg` (rejects empty, leading `-`, whitespace/control bytes) before any spawn. Map `SpawnError.FileNotFound` to `BinaryNotFound`; a subprocess failure must surface as `<prefix>: <message>` on stderr with a non-zero exit, never a panic.
- `Runner.capture` is the plain form; `Runner.captureWith` adds `CaptureOptions` (stdin bytes, stdout/stderr limits, timeout). Feeding stdin exists so a secret can reach a child without touching argv; it is capped at `process.max_stdin_bytes` (4 KiB) because the whole payload is written before either output stream is drained, so it must fit in one pipe buffer or the two processes deadlock.
- Commands carry `git_runner: ?git.Runner = null` (and `auth`/`config` carry `credential_runner: ?process.Runner = null`) on their `Context`. `null` means "no process execution", which is what keeps tests hermetic: `main.zig` installs the system runner, tests inject `FakeProcess` (`src/tests/main.zig`), and no test ever shells out or depends on this repo's branch. Never default those fields to the system runner.
- `git.zig` imports only std and `process`, and `credentials.zig` only `config` and `process` — none of which has a mocked variant — so a single `git_mod`/`process_mod`/`credentials_mod` serves the exe, both command module variants, and the npm cross-builds. There is deliberately no `*_test_mod` for any of them.
- Branch inference is `git symbolic-ref --short HEAD` plus `git.matchIdentifier` (leftmost `\b([A-Za-z0-9]+)-([1-9][0-9]*)\b`, team key uppercased). Detached HEAD is not an error — it is a distinct result, told apart from "not a git repository" by a `git rev-parse --is-inside-work-tree` probe. Do not slugify branch names locally: `issue start` uses Linear's own `Issue.branchName`.
- `linear milestone` keeps all five verbs in one module (`src/commands/milestones.zig`) the way `issue_comments.zig` does: they share the `ProjectMilestone` field projection, the project resolver, and the sort-order renderer. `list` always goes through the **root** `projectMilestones` query: `--project` only adds `filter: { project: { id: { eq: <uuid> } } }`, and omitting it lists the whole workspace — one code path, not two. `--project` accepts a uuid (no lookup), a slug, or an exact name; a name that matches more than one project is an error, never a silent pick. Because an unscoped listing mixes projects, `project` is in `milestone_default_fields` unconditionally, exactly like `team` on `state_default_fields`; do not make it conditional on the flag, a default field set that changes shape with a flag is unscriptable. `sortOrder` is a GraphQL Float, so it leaves as a JSON number, not the string the flag arrived as.
- `--bulk`/`--bulk-file`/`--bulk-stdin` on the delete commands go through `src/commands/bulk.zig`, which owns flag parsing, dedupe, and per-item accounting. It is separate from `common.zig` on purpose — `common.zig` is the GraphQL request/response layer, this is batch bookkeeping. Execution is **serial and must stay that way**: every caller is a destructive mutation and nothing else in this codebase runs concurrently. A per-item failure is counted and the run continues; only writer/allocator errors abort. The summary line goes to stderr and is suppressed under `--json`, where per-item documents are wrapped in one array instead.
- `gql --paginate` validates the document up front (`$after` must be *declared*, not just referenced; `pageInfo`/`hasNextPage`/`endCursor` must all appear) and finds the connection breadth-first in the response, so the shallowest `nodes`+`pageInfo` object wins. Every page's `Response` is kept alive until printing because the merged document borrows node values from all of them — same reason every `*list` command accumulates whole responses. `--max-pages` (default 20) is the loop bound; hitting it warns on stderr and still returns what was collected.
- Validation that does not gate the write is worse than none: it implies a check happened while the exit status says success. `config set default_team_id` refuses to persist a team the workspace does not have, and keeps that verdict distinct from a lookup that never completed (`could not verify team` vs `not found in workspace`) so a timeout is never reported as a missing team. Same rule anywhere else validation is added.
- Flags must reach the API or not exist. `issue delete --reason` was removed rather than deprecated because `issueDelete` takes only `(id, permanentlyDelete)` — the value was echoed into this CLI's own output and read like an audit trail in Linear. Do not add a flag whose only effect is on local output while naming something the API owns.
- GraphQL client already handles HTTP status + GraphQL errors; retries only for 5xx with small backoff. Preserve explicit error messaging.
- Tests: offline unit coverage exists for config, flag parsing, printer; keep them passing. Online tests are gated by env and should remain optional.
